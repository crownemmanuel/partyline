# PartyLine Control Protocol v1

The contract between the server (Tauri desktop) and every client (iOS, Android, web,
desktop-as-client). **Change this file first, then the code.** `apiVersion` is `1`.

All JSON. Field names are camelCase. Timestamps are ISO 8601 UTC strings. IDs:

- `deviceId`: UUID v4, generated by the device.
- `groupId`: slug `[a-z0-9-]{1,32}`, generated by the server from the name (`camera`).
- Target refs: `"all"`, `"g:<groupId>"`, `"d:<deviceId>"`.

Base URL: `https://<host>:8443`. The host is found via mDNS, QR, or typed by hand.

## 1. Discovery (mDNS / DNS-SD)

```
Service:  _partyline._tcp.local
Port:     8443
TXT:      v=1 id=<server uuid> name=<server name> fp=<sha256 of DER cert, lowercase hex>
```

Join link (QR and deep link): `https://<ip>:8443/#join?code=<6 digits>&fp=<fp>&id=<server uuid>`

## 2. REST

Errors are `{"error": {"code": "<snake_case>", "message": "<human>"}}` with a matching HTTP
status. Codes used: `invalid_code`, `join_closed`, `rate_limited`, `revoked`, `invalid_token`,
`not_admin`, `not_found`, `bad_request`, `version_unsupported`.

### GET /api/info  (no auth)

```json
{
  "apiVersion": 1,
  "serverId": "6e2a…",
  "name": "Emmanuel's MacBook",
  "appVersion": "0.1.0",
  "fingerprint": "ab12…",
  "joinOpen": true,
  "livekitUrl": "/rtc",
  "minClientVersion": "0.1.0"
}
```

### POST /api/join  (no auth, rate limited)

```json
{ "joinCode": "483920", "deviceId": "0f3c…", "displayName": "Camera 2",
  "platform": "ios", "appVersion": "0.1.0", "apiVersion": 1 }
```

200:

```json
{ "deviceToken": "base64url 32 bytes, shown once",
  "livekitToken": "<jwt>", "livekitUrl": "/rtc", "roomName": "partyline",
  "me": { …Device… }, "groups": [ …Group… ] }
```

If `deviceId` already exists and is not revoked, the server treats this as a re-pairing:
keeps group and permissions, issues a new device token, invalidates the old one.

401 `invalid_code`, 403 `join_closed`, 429 `rate_limited` (`Retry-After` header).

### POST /api/session  (device token)

`Authorization: Bearer <deviceToken>`. Body: `{ "appVersion": "0.1.0", "apiVersion": 1 }`.

200: same as join without `deviceToken`. 401 `invalid_token`, 403 `revoked`.
Clients call this on every launch and whenever the LiveKit token expired while offline.

### GET /api/messages?since=<iso>&limit=100  (device token)

Messages addressed to this device (direct, its groups, or all), newest last.

### GET /  and static files

The web client. `/#join?…` is handled by the client. `GET /healthz` returns `ok`.

### /rtc  (WebSocket, proxied to LiveKit)

LiveKit SDKs connect to `wss://<host>:8443/rtc` with the LiveKit token. The server forwards
to `ws://127.0.0.1:7880`. Nothing to implement on the client beyond passing the URL.

## 3. WebSocket /api/ws

Connect to `wss://<host>:8443/api/ws`. First message must be `auth` within 5 s.

Envelope for every message in both directions:

```json
{ "type": "state.set", "id": "c-17", "ts": "2026-11-05T18:02:11Z", "payload": { … } }
```

- `id` is optional; the server replies with `ack` or `error` carrying `replyTo` when present.
- Client sends `ping` every 15 s; server answers `pong`. No pong for 30 s → reconnect.
- On reconnect the server sends a full `welcome` again. Clients replace, not merge.

### 3.1 Client → Server (any device)

| type | payload | notes |
|---|---|---|
| `auth` | `{ "deviceToken": "…", "appVersion": "…" }` | must be first |
| `ping` | `{}` | |
| `state.set` | `{ "talkTargets"?: ["g:camera"], "listenGroupIds"?: ["camera"], "micLive"?: bool, "speakerMuted"?: bool, "talkMode"?: "ptt"\|"latch" }` | partial; server validates against permissions and broadcasts |
| `status` | `{ "rtcConnected": bool, "speaking": bool, "battery"?: 0-100, "charging"?: bool, "headset"?: bool, "rttMs"?: number, "outputRoute"?: "headset"\|"speaker"\|"earpiece"\|"bluetooth" }` | send on change, at most every 2 s |
| `message.send` | `{ "to": "g:camera" \| "d:<id>" \| "all", "text": "…", "kind": "text"\|"quick" }` | non-admin may target: own groups, admins (`d:`), or `all` only if `settings.crewCanBroadcast` |
| `message.ack` | `{ "messageId": "…" }` | read receipt |
| `signal.send` | `{ "to": "g:…" \| "d:…" }` | attention buzz |
| `token.refresh` | `{}` | asks for a new LiveKit token early |

### 3.2 Client → Server (admin only; `not_admin` error otherwise)

| type | payload |
|---|---|
| `admin.device.update` | `{ "deviceId", "displayName"?, "groupId"?, "listenGroupIds"?, "canTalkGroupIds"?, "isAdmin"?, "forcedTalkMode"?: "ptt"\|null }` |
| `admin.device.mute` | `{ "deviceId", "muted": bool }` → server also calls LiveKit MuteTrack |
| `admin.device.remove` | `{ "deviceId" }` → revoke token, remove participant, send `kicked` |
| `admin.device.forget` | `{ "deviceId" }` → delete the row (offline stale devices) |
| `admin.group.create` | `{ "name", "color"?, "defaultTalkMode"? }` |
| `admin.group.update` | `{ "groupId", "name"?, "color"?, "sortOrder"?, "defaultTalkMode"? }` |
| `admin.group.delete` | `{ "groupId", "moveDevicesTo": "<groupId>" }` |
| `admin.join.rotate` | `{}` → new code in `server.updated` |
| `admin.join.setOpen` | `{ "open": bool }` |
| `admin.settings.update` | `{ "serverName"?, "crewCanBroadcast"?, "defaultTalkMode"? }` |

### 3.3 Server → Client

| type | payload | notes |
|---|---|---|
| `welcome` | `{ "me": Device, "devices": [Device], "groups": [Group], "server": ServerInfo, "settings": Settings, "livekitToken", "roomName", "messages": [Message] (last 50 for me) }` | full snapshot after auth and after every reconnect |
| `ack` | `{ "replyTo": "c-17" }` | |
| `error` | `{ "replyTo"?: "…", "code", "message" }` | |
| `pong` | `{}` | |
| `device.upsert` | `Device` | one device changed (state or config); replace by id |
| `device.removed` | `{ "deviceId" }` | forgotten or removed |
| `groups.updated` | `{ "groups": [Group] }` | whole list |
| `server.updated` | `ServerInfo` | join code, name, joinOpen |
| `settings.updated` | `Settings` | |
| `message` | `Message` | |
| `message.acked` | `{ "messageId", "deviceId", "ts" }` | admins only |
| `signal` | `{ "from": "<deviceId>", "to": "g:…"\|"d:…" }` | buzz + tone |
| `token.refreshed` | `{ "livekitToken" }` | sent ~5 min before expiry or on request |
| `admin.notice` | `{ "kind": "muted"\|"unmuted"\|"moved"\|"renamed"\|"forcedPtt", "text": "You were moved to Backstage" }` | show a toast / notification |
| `kicked` | `{ "reason": "removed_by_admin" }` | client leaves room, deletes token, shows join screen |
| `server.shutdown` | `{ "reconnectAfterMs": 3000 }` | host is closing; keep call alive, retry discovery |

### 3.4 Objects

```ts
type Platform = "ios" | "android" | "web" | "desktop";
type TalkMode = "ptt" | "latch";
type TargetRef = "all" | `g:${string}` | `d:${string}`;

interface Group {
  id: string; name: string; color: string; sortOrder: number;
  defaultTalkMode: TalkMode | null;
}

interface Device {
  id: string; displayName: string; platform: Platform; appVersion: string;
  groupId: string;                 // home group
  listenGroupIds: string[];        // saved preference, default [groupId]
  canTalkGroupIds: string[];       // permission, default [groupId]
  isAdmin: boolean;
  forcedTalkMode: TalkMode | null;
  adminMuted: boolean;
  createdAt: string; lastSeenAt: string;
  live: {
    online: boolean;               // control WS up
    rtcConnected: boolean;
    micLive: boolean;
    speakerMuted: boolean;
    talkMode: TalkMode;
    talkTargets: TargetRef[];      // never includes "all"; server expands it
    speaking: boolean;
    battery: number | null; charging: boolean | null;
    headset: boolean | null; outputRoute: string | null;
    rttMs: number | null;
  };
}

interface ServerInfo {
  serverId: string; name: string; appVersion: string; apiVersion: 1;
  joinCode: string | null;         // null for non-admins
  joinOpen: boolean; fingerprint: string;
  failedJoinAttempts: number;      // admins only, last hour
}

interface Settings { crewCanBroadcast: boolean; defaultTalkMode: TalkMode; quickReplies: string[]; }

interface Message {
  id: string; from: string;        // deviceId
  to: TargetRef; kind: "text" | "quick";
  text: string; ts: string;
  ackedBy?: string[];              // admins only
}
```

## 4. Validation rules (server)

- `talkTargets` groups must be in `canTalkGroupIds`; device targets must be an admin, a
  member of a group the sender may talk to, or any device if sender is admin. Admin may
  target any group. `"all"` from a client is expanded to every group the sender may talk to.
- `listenGroupIds` ⊆ groups the device may listen to. Non-admins: own group plus any
  group where `canTalkGroupIds` includes it. Admins: any.
- `talkMode` is ignored if `forcedTalkMode` is set; the server reports the forced one.
- `micLive: true` is ignored while `adminMuted`.
- Message `text` ≤ 500 chars. Quick replies must match `settings.quickReplies`.
- Everything the server rejects produces `error` with `replyTo`; state is unchanged.

## 5. LiveKit mapping

| LiveKit | PartyLine |
|---|---|
| Room name | `partyline` |
| Participant identity | `deviceId` |
| Participant name | `displayName` |
| Participant metadata | JSON `{ "groupId", "isAdmin" }` set by server on token issue |
| Track | exactly one, source `microphone`, name `mic`, always published, muted when not live |
| Token grants | `roomJoin`, `room: "partyline"`, `canPublish: true`, `canPublishSources: ["microphone"]`, `canSubscribe: true`, `canPublishData: false`, TTL 1h |
| Admin mute | server → RoomService `MuteTrack(identity, trackSid, muted=true)` |
| Remove | server → RoomService `RemoveParticipant(identity)` |

### 5.1 Routing algorithm (identical on every client)

Run whenever `welcome`, `device.upsert`, `device.removed`, or `groups.updated` arrives, and
whenever my own `talkTargets` or `listenGroupIds` change.

```
me = roster[myId]

# Publisher side: who may receive my audio
allowed = set()
for d in roster where d.id != myId:
    if any("g:" + g in me.live.talkTargets for g in d.listenGroupIds): allowed.add(d.id)
    if "d:" + d.id in me.live.talkTargets: allowed.add(d.id)
    if d.isAdmin and me.live.talkTargets is non-empty and settings.adminsHearEverything: allowed.add(d.id)   # default false
localParticipant.setTrackSubscriptionPermissions(allParticipantsAllowed=false, allowed)

# Receiver side: what I play
for p in remoteParticipants:
    d = roster[p.identity]
    hear = d and not d.adminMuted and (
            any("g:" + g in d.live.talkTargets for g in me.listenGroupIds)
            or "d:" + myId in d.live.talkTargets)
    audioTrack.enabled = hear and not me.live.speakerMuted and not localMute[d.id]
    audioTrack.volume  = localVolume[d.id] (default 1.0)
```

Subscribe to every remote audio track (LiveKit `autoSubscribe: true`); the server only
forwards permitted ones, and the receiver rule decides playback. `talkTargets` changes
reach other clients via `device.upsert` within one round trip, so a producer switching from
Camera to Backstage is heard correctly within ~50 ms on a LAN.

## 6. Client behaviors every platform must implement

1. On launch: load `deviceId` + `deviceToken`; if present → `POST /api/session`; else show
   discovery/join. On `revoked` → delete token, show join.
2. Connect WS → `auth` → wait for `welcome` → connect LiveKit → publish muted mic →
   run routing → report `status` and `state.set` with the restored `talkMode`.
3. PTT: on press `state.set {micLive:true}` and unmute track locally **at the same time**
   (do not wait for ack). On release the reverse. Haptic on both.
4. "Reply to producer": while held, `talkTargets = ["d:<first online admin>"]`, restore after.
5. Apply `admin.notice`, `kicked`, `token.refreshed`, `server.shutdown` as described.
6. Reconnect with backoff 1, 2, 4, 8, 15, 15… seconds; keep the platform call alive
   meanwhile; if the server id disappears from mDNS for > 60 s show "Server offline".
7. Messages: show as notification when backgrounded, play a short tone, vibrate; `signal`
   vibrates + tone even when speaker-muted.
8. Send `status` at most every 2 s, and immediately on `rtcConnected`/`speaking`/route change.

## Proposed protocol change (from the desktop session, 2026-11-06) — items 1–3 additive; item 4 needs native apps to re-prompt on a changed fingerprint

1. `GET /api/info` may include `"localHost": true`. Only the host's **loopback** listener
   (`http://127.0.0.1:8442`, used by the desktop's own webview) sends it; on that listener
   `POST /api/join` needs no `joinCode` and the device becomes admin. Phones never see it and
   should ignore unknown fields.
2. Clarification of §2 `/rtc`: SDKs append their own `/rtc…` path to the URL they are given. Give
   them `wss://<host>:8443/rtc`; the server strips one `/rtc` prefix, so `/rtc/rtc?…`,
   `/rtc/rtc/v1?…` and `/rtc/rtc/validate?…` all reach LiveKit.
3. Clarification of `admin.device.mute {muted:false}`: LiveKit only allows server-side *mute*. Unmute
   clears `adminMuted`; the client's track unmutes on its next PTT/latch press.
4. **TLS certificate profile (changes ARCHITECTURE §5.3 "valid 10 years").** iOS Safari refuses
   server certs valid for more than 825 days or lacking `extendedKeyUsage=serverAuth`, and shows
   **no** "visit this website" option, so phone browsers could not join. Servers now issue a
   P-256 cert valid **820 days** with `keyUsage=digitalSignature`, `extendedKeyUsage=serverAuth`
   and `basicConstraints=CA:FALSE`, and replace it automatically 30 days before expiry (and once,
   on upgrade, if the stored cert lacks this profile). **Consequence for native apps:** the
   fingerprint now changes on renewal (about every 26 months) as well as on SAN/IP changes, so
   clients must handle a changed fingerprint for a known `serverId` by showing the trust prompt
   again (new `fp` comes from mDNS TXT or the QR link), not by failing permanently.
5. **App downloads (additive).** `GET /api/info` adds `androidApk: {url, size} | null` (the
   Android APK bundled with the host, served at `GET /download/partyline.apk` as
   `application/vnd.android.package-archive`) and `iosInstallUrl: string | null` (an https link,
   e.g. a TestFlight public link). `Settings` gains `iosInstallUrl?: string | null`, set via
   `admin.settings.update {iosInstallUrl}`; only `https://` URLs are accepted, and null or "" clears it.
   The web client's `/#install[&code=…&fp=…&id=…]` page uses these to show install steps.
   Clients can ignore all of it.
